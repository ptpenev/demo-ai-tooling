## Tribal Knowledge

### Team Conventions
- Strict Monorepo structure: `apps/api` for backend, `apps/web` for frontend. Do NOT mix code.
- Use Drizzle ORM for all database interactions. No raw SQL unless unavoidable.
- Generate migrations via `drizzle-kit generate`; never modify tables manually.
- Use Service Layer pattern for business logic and Repository pattern for data access.
- API endpoints must be versioned (e.g., `/api/v1/...`).
- UI must be built with `shadcn/ui` components and TailwindCSS. Do not create backend-rendered templates.

### Lessons Learned
- Ensure all input is validated using NestJS `ValidationPipe`
- Optimize queries by selecting only necessary columns, using pagination for lists, and eager loading relations (avoid N+1)

### Historical Decisions
- Chosen Monorepo architecture for NestJS + React
- Chosen Drizzle ORM over other ORMs for PostgreSQL
- Chosen Zustand for frontend state and React Query for data fetching
- Chosen shadcn/ui and TailwindCSS for standardized and accessible UI components

## Governance

### Amendment Process
Any team member can propose amendments via pull request. Changes are discussed

Code reviewers validate compliance during PR review. Constitution violations
should be flagged and addressed before merge, particularly regarding architectural separation, Drizzle ORM usage, and `endpoints.md` updates.

### Exception Handling
Exceptions discussed case-by-case with team. Strong justification required, especially for using raw SQL queries.
